# Motion Playground 数据与步骤组件设计规格

## 目标

在现有 `MetricFocus`、`CompareSplit`、`ProfileReveal` 之后新增三个短视频叠加动效组件：

4. `BarCompare`：最多四项的柱状数据对比。
5. `ShareRing`：最多四项的环形占比图。
6. `StepFlow`：最多五步的流程讲解图。

三个组件继续服务横版口播短视频，不引入时间轴、Remotion、ffmpeg 或视频导出能力。完成后组件库总数为六个。

## 统一视觉方向

采用 **Precision Spatial**，以苹果式空间秩序和材质克制为参考，同时延续现有预览台的精密科技感。

- 色彩以黑、炭灰、冷白为主，不依赖彩色分类。
- 重点通过面积、宽度、高度、粗细、明度和留白变化表达。
- 只使用极轻微背景模糊，不使用厚重玻璃卡、大阴影、霓虹或渐变色块。
- 主要图形使用冷白，次要图形按重要性递减为三档灰阶。
- 圆角只用于环形图和必要端点；柱体、步骤线与信息边界保持精确、克制。
- 数字与短标签使用等宽字体，中文标题使用现有几何展示字体。

## 人物安全区

三个组件继续遵守现有口播画布约束：

- 人物安全区：横向约 `39%–86%`、纵向约 `6%–95%`。
- 左侧主动效区：横向约 `4%–35%`，承载图形、标题和主要标签。
- 右侧辅助区：横向约 `87%–97%`，只显示一个结论、当前状态或重点值。
- 图形、文字、连接线、动画轨迹和装饰元素都不得进入人物安全区。
- 安全区辅助线只用于预览，不属于组件内容。

## 组件 04：BarCompare

### 用途

用于比较二至四项数据，例如季度变化、不同方案效果或多个渠道表现。

### 信息结构

左侧主卡包含：

- 分类眉题。
- 对比标题。
- 二至四根柱体。
- 每根柱体的短标签和数值。
- 一条统一基线。

右侧辅助条包含：

- `PEAK` 或自定义结论标签。
- 重点项数值。
- 重点项名称与差值说明。

### 视觉层级

- 所有柱体共享同一基线。
- 普通柱体宽度一致，使用三档灰阶。
- 重点柱体宽度约为普通柱体的 `1.18` 倍，使用冷白，并保持最高视觉权重。
- 柱间距较大，避免形成传统后台统计图的拥挤感。
- 不显示完整纵轴、密集刻度和网格，只保留基线与必要参考短线。

### 动效节奏

1. 基线由左向右展开。
2. 柱体从基线依次生长，每根错峰约 `0.12s`。
3. 标签与数值在对应柱体接近终点时淡入。
4. 重点柱体轻微增宽并提升明度。
5. 右侧结论最后进入，停留后整体循环。

减少动态效果时直接显示最终状态，不执行高度变化和循环。

### 参数

- 眉题、标题。
- 二至四项标签。
- 二至四项数值，范围 `0–9999`。
- 数值后缀。
- 重点项索引。
- 右侧结论标签与说明。
- 循环时长。

有效值不足两项时使用默认占位数据；非法重点索引回退到最大值项。

## 组件 05：ShareRing

### 用途

用于表达二至四项占比，例如用户构成、渠道来源或预算分配。

### 信息结构

左侧主卡包含：

- 分类眉题。
- 占比标题。
- 一个主环形图。
- 中心主占比和主项名称。
- 环形图下方的精简图例。

右侧辅助条包含：

- `SHARE` 或自定义结论标签。
- 主占比。
- 主项名称或排序信息。

### 视觉层级

- 使用环形图而非实心饼图，为中心核心数字留出呼吸空间。
- 最大占比扇区最亮、最粗；其余扇区按占比顺序逐级降低明度和弧宽。
- 扇区之间保留极小黑色间隔，确保灰阶相近时仍可区分。
- 图例最多四项，仅显示短名称和百分比，不使用彩色圆点。
- 不使用 3D、投影、彩色渐变或爆炸扇区。

### 动效节奏

1. 环形轨道以整圆细线出现。
2. 各占比弧段按顺序沿顺时针绘制。
3. 主扇区完成后加粗并锁定为冷白。
4. 中心百分比从零计数。
5. 图例逐项出现，右侧主占比最后进入。

减少动态效果时直接显示完整环形图和最终数字。

### 参数

- 眉题、标题。
- 二至四项名称。
- 二至四项数值，范围 `0–10000`。
- 主项索引。
- 中心标签。
- 右侧结论标签与说明。
- 循环时长。

组件内部根据有效项总和计算百分比；总和为零时使用等分结果，避免无效圆弧。

## 组件 06：StepFlow

### 用途

用于解释三至五步的操作流程、方法论或项目进度。

### 信息结构

左侧主卡包含：

- 分类眉题。
- 流程标题。
- 三至五个纵向步骤。
- 每步编号和短标题。
- 步骤之间的细连接线。

右侧辅助条包含：

- `CURRENT` 或自定义状态标签。
- 当前步骤编号。
- 当前步骤短标题和状态说明。

### 视觉层级

- 当前步骤整体高度约为普通步骤的 `1.5` 倍。
- 当前编号、标题和分隔线使用冷白；已完成步骤使用中灰；未到达步骤使用深灰。
- 普通步骤保持紧凑，当前步骤增加上下留白。
- 连接线只承担顺序关系，不使用箭头、彩色节点或复杂流程分支。
- 五步必须在左侧卡片内完整显示，任何一步都不进入人物安全区。

### 动效节奏

1. 标题和纵向连接线出现。
2. 第一步进入焦点并放大，右侧同步显示 `01`。
3. 焦点按顺序向下移动；前一步缩回并转为已完成灰阶。
4. 每一步停留时间均匀，最后一步停留略长。
5. 完成后所有步骤短暂显示为已完成状态，再淡出循环。

正常循环从初始焦点步骤开始并依次遍历全部有效步骤；减少动态效果时只显示该焦点步骤的静态状态。

### 参数

- 眉题、标题。
- 三至五个步骤标题。
- 初始焦点步骤索引。
- 右侧状态标签与说明。
- 单步停留时间。
- 循环开关使用现有预览台行为，不增加单独播放控制。

不足三步时补充默认占位步骤；超出五步时只读取前五步。

## 注册表与参数边界

- `MotionId` 新增 `bar-compare`、`share-ring`、`step-flow`。
- 三个组件分别拥有独立参数类型、默认值、测试和样式命名空间。
- 注册表编号依次为 `04`、`05`、`06`，现有前三个组件顺序不变。
- 通用参数面板继续使用文本、数值和选择控件。
- 为避免增加动态数组编辑器，本阶段把每个数据项或步骤展开为明确字段，例如 `item1Label`、`item1Value`。
- 空项通过标签是否为空判断，不为本阶段新增增删按钮或拖拽排序。
- 现有 `playbackKey`、重新播放、恢复默认和安全区开关逻辑保持不变。

## 动效实现边界

- 使用 Motion for React 编排入场、错峰、计数和循环。
- 环形图使用 SVG 圆弧和 `stroke-dasharray`，不引入图表库。
- 柱状图和步骤图使用语义化 React 结构与 CSS，不引入 Canvas。
- 可以提取轻量的数值归一化和百分比计算函数，但不建立通用图表引擎。
- 动效必须由参数确定，组件不读取工作台状态。

## 测试与验收

### 自动化测试

- 注册表包含六个唯一组件，编号为 `01–06`。
- 三个新组件渲染标题、所有有效数据项和左右安全区标记。
- `BarCompare` 正确识别重点项并夹紧非法数值。
- `ShareRing` 正确计算百分比，覆盖总和为零的回退。
- `StepFlow` 支持三至五步并正确显示当前步骤。
- 参数修改、恢复默认和重新播放继续工作。
- 尊重 `prefers-reduced-motion`。

### 浏览器验收

- 六个组件入口完整显示，组件栏允许滚动且页脚仍可访问。
- 三个新组件在人物参考图上清晰可读。
- 左侧主卡右边界小于人物安全区左边界；右侧辅助条左边界大于人物安全区右边界。
- 最大允许文本和最大数据项数量下没有横向或纵向溢出。
- 重点信息主要依赖尺寸和明度表达，画面不存在明显高饱和颜色。
- 动画完整循环、参数实时更新、恢复默认和重新播放均正常。
- 全量测试、ESLint、TypeScript 和生产构建通过。

## 明确不做

- 不增加折线图、雷达图、地图或组合图表。
- 不增加图表数据导入、CSV、JSON 编辑器或数据库。
- 不增加拖拽排序、步骤分支、时间轴、播放头和导出。
- 不替换或删除现有三个组件。
