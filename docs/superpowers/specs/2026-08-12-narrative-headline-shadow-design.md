# 叙事卡片白字阴影设计

日期：2026-08-12

## 目标

为“叙事（narrative）”卡片上方两行白色主标题增加深灰色阴影，提高标题在人物、灯光和其他复杂视频背景上的可读性。

## 视觉规格

采用 A“柔和可读阴影”方案：

- 阴影颜色：深灰 `rgb(38, 40, 43)`；
- 阴影透明度：80%，即 `rgba(38, 40, 43, 0.8)`；
- 水平偏移：4px；
- 垂直偏移：5px；
- 模糊半径：10px。

阴影只应用于 `line1` 和 `line2` 两行 90px 白色主标题。以下内容保持不变：

- `NARRATIVE / 01` 蓝色眉题；
- 蓝色分隔线；
- 底部灰色说明文字；
- 标题原有字体、字号、位置、颜色、模糊入场、透明度和运动节奏。

## 实现方式

实时预览和透明导出共用 `src/motion/canvas/narrativeRenderer.ts`，因此阴影直接在 Canvas 标题绘制阶段设置，不增加仅供预览使用的 CSS 或第二套渲染路径。

Canvas 绘制标题时设置：

```ts
shadowColor: 'rgba(38, 40, 43, 0.8)'
shadowBlur: 10
shadowOffsetX: 4
shadowOffsetY: 5
```

阴影配置应成为 `drawText` 的可选参数，由绘制工具在自身 `save()` / `restore()` 生命周期内应用。这样可确保阴影不会泄漏到眉题、分隔线或底部说明文字，也便于测试和后续复用。

## 边界和兼容性

- 阴影不会改变文字测量、换行或最大宽度计算。
- 标题原有左半区安全边界保持不变。
- 阴影向右和向下的视觉扩展量较小，不会进入人物安全线或字幕安全区。
- 入场模糊滤镜与阴影同时存在；标题本体仍按原状态控制透明度和滤镜值。
- 参数结构、默认值、项目存储格式和导出合同均不改变。

## 验证

自动化测试覆盖：

1. 两行白色主标题绘制时使用 `rgba(38, 40, 43, 0.8)`。
2. 两行标题分别使用 10px 模糊、4px 水平偏移和 5px 垂直偏移。
3. 蓝色眉题和底部灰色说明文字不使用阴影。
4. 标题原有入场模糊测试继续通过。
5. 完整测试套件和生产构建通过。

浏览器人工检查默认叙事内容，确认阴影能提高复杂视频背景上的白字可读性，同时不形成明显描边、重影或脏边。

## 完成标准

- 仅两行白色主标题出现深灰 80% 柔和阴影。
- 标题更加清楚，但整体仍保持当前克制的工程视觉风格。
- 实时预览与透明导出效果一致。
- 现有布局、动画和安全区不发生回归。
