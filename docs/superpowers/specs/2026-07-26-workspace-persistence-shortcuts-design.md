# Overlay Studio 本地恢复与快捷操作设计

## 目标

在现有 Overlay Studio 时间轴编辑器中增加三组能力：

1. 双击左侧组件主体，在当前视频播放头快速添加卡片。
2. 时间轴已有选中卡片时，按 `Delete` 删除该卡片。
3. 自动保存本地视频和效果工作区，刷新页面后恢复；提供带确认流程的“清空工作区”。

本阶段仍然是纯本地网页编辑器，不上传视频，不接入 Remotion、ffmpeg
或视频导出。

## 用户流程

### 快速添加

- 单击组件主体继续执行原有的组件预览和参数切换。
- 点击组件右侧 `+` 继续在当前播放头添加。
- 双击组件主体与 `+` 使用同一条创建逻辑。
- 一次双击只创建一张卡片；双击过程中产生的单击事件只切换预览，
  不额外创建卡片。
- 没有视频或视频短于最小卡片时长时，沿用现有中文状态提示，不创建卡片。

### Delete 删除

- 选中时间轴片段后，按 `Delete` 删除选中的卡片。
- 焦点位于输入框、文本域、下拉框、滑块或可编辑区域时，不响应全局删除，
  避免用户编辑参数时误删卡片。
- 时间轴片段按钮获得焦点时，`Delete` 可以删除该片段。
- 现有删除按钮、指针操作和键盘方向键微调保持不变。

### 自动恢复

- 视频确认可以播放后，保存视频 Blob 和文件元数据。
- 时间轴、参数或工作区设置发生变化后，约 300ms 防抖保存。
- 刷新页面后自动读取本地数据库并恢复视频及效果。
- 恢复的视频从 0 秒开始，保持暂停和静音，不恢复上次播放进度。
- 恢复完成前禁止空白初始状态覆盖数据库中的有效数据。

### 清空工作区

- 右侧“项目文件”区域增加“清空工作区”按钮。
- 点击后打开中文确认弹窗，说明将删除本地视频和全部效果。
- 用户可以取消、按 `Escape` 关闭，或确认清空。
- 确认后，在同一数据库事务中删除视频和工作区记录；事务成功后才重置界面。
- 重置内容包括视频、时间轴卡片、组件参数、当前组件选择、安全区设置、
  选中状态和临时错误。
- 清空后界面与首次打开状态一致。

## 持久化架构

新增 `src/persistence/workspaceStorage.ts`，封装 IndexedDB，不让 React
组件直接操作数据库 API。

数据库：

- 名称：`overlay-studio`
- 版本：`1`
- `workspace` object store：保存单条 `current` 工作区快照。
- `assets` object store：保存单条 `video` 视频 Blob 和文件元数据。

分开 object store 的原因是：拖动卡片或修改参数时只写轻量工作区快照，
不会重复写入大型视频 Blob。更换视频和清空工作区时使用跨 store 事务，
保证视频元数据和资源一致。

### 工作区快照

```ts
interface PersistedWorkspaceV1 {
  version: 1
  project: OverlayProject
  parametersByMotion: Record<MotionId, ParameterValues>
  activeId: MotionId
  showSafeArea: boolean
  video: {
    present: boolean
    name?: string
    type?: string
    lastModified?: number
  }
}
```

不保存：

- Blob URL
- 当前播放进度
- 播放/暂停状态
- 声音状态
- 当前选中的时间轴卡片
- 动画 replay revision
- 文件读取中间状态和错误提示

### 视频记录

```ts
interface PersistedVideoV1 {
  version: 1
  blob: Blob
  name: string
  type: string
  lastModified: number
}
```

恢复时通过 `URL.createObjectURL(blob)` 生成新的会话 URL，组件卸载、更换视频、
移除视频和清空工作区时继续执行现有 URL 回收逻辑。

## React 数据流

`Workbench` 增加明确的 hydration 生命周期：

1. 首次挂载进入 `loading`。
2. 并行读取工作区和视频记录。
3. 使用现有 `parseOverlayProject` 与 motion defaults 校验持久化项目。
4. 校验成功后原子恢复 cards、参数、activeId 和安全区。
5. 视频记录与 `video.present` 一致时创建 Blob URL，并标记为恢复视频。
6. 恢复结束后进入 `ready`，此后才启用自动保存。

自动保存：

- cards、组件参数、activeId、showSafeArea 改变时安排 300ms 防抖写入。
- 新变化会取消前一次计时。
- 组件卸载时取消计时。存储层串行执行写入；写入进行中出现的新快照只保留
  最新一份，并在当前事务完成后继续保存，避免旧事务晚提交覆盖新状态。
- 导入 JSON、删除卡片、移动位置、恢复默认等都通过同一工作区状态入口，
  因而自动纳入保存。

视频保存：

- 新视频只有通过现有 `onVideoReady` 确认后才写入 IndexedDB。
- 视频解码失败时不替换已保存的视频。
- “移除视频”删除 `assets/video`，但保留时间轴和效果。

## 恢复播放策略

`PreviewStage` 区分新导入视频和恢复视频：

- 新导入视频保持当前自动播放体验。
- 恢复视频加载后设置 `currentTime = 0`、`muted = true` 并保持暂停。
- 用户之后可以正常使用播放、声音和进度控制。

## 错误处理

- IndexedDB 不可用或读取失败：显示“本地工作区恢复失败”，应用使用空白工作区。
- 配额不足或写入失败：当前会话继续可用，显示
  “本地保存失败，刷新后可能无法恢复”。
- 持久化项目结构无效：不载入损坏数据，显示“本地工作区数据无效”。
- 清空事务失败：显示“清空本地数据失败”，不重置当前界面，避免刷新后旧数据重新出现。
- 错误状态不会阻塞视频播放、参数编辑或手动 JSON 导入导出。

## 清空确认弹窗

新增小型受控确认组件，使用：

- `role="alertdialog"`
- `aria-modal="true"`
- 明确标题和后果说明
- “取消”与“确认清空”两个原生按钮
- 打开后聚焦“取消”
- `Escape` 取消
- 关闭后焦点返回“清空工作区”按钮

不使用浏览器原生 `confirm()`，以保持现有中文铅笔风格和可测试性。

## 测试策略

### 单元测试

- IndexedDB 打开、保存、读取、删除和跨 store 清空。
- 工作区版本及持久化数据校验。
- 旧写入不会覆盖新写入。
- 双击组件只调用一次 `onAddMotion`，单击行为不回归。
- Delete 删除选中卡片；输入框、滑块和可编辑区域不触发。
- 清空确认、取消、`Escape` 和焦点恢复。

### 集成测试

- 视频成功载入后写入 Blob；失败视频不覆盖旧记录。
- 刷新模拟后恢复视频、cards、参数、位置、activeId 和安全区。
- 恢复视频从 0 秒开始、暂停、静音。
- hydration 期间不会用空状态覆盖已有快照。
- 双击在当前播放头创建一张 3 秒卡片。
- 选中片段后 Delete 删除并自动保存。
- 确认清空后数据库和界面同时回到初始状态。
- 清空失败时界面数据保持。
