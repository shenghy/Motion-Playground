# 投票卡片与安全布局设计

## 目标

本次修改解决三个问题：缩窄“步骤流程”卡片，使其不越过视频中的人物保护线；把左侧动效组件库改成与右侧参数面板一致的深灰色层级；新增“投票卡片”，用于在口播视频中发起观众投票并鼓励弹幕或评论互动。

## 已确认的视觉方向

投票卡片采用 A 方案“编号投票”。画面包含蓝色英文眉题、投票标题、二至四个编号选项，以及底部弹幕或评论引导语。卡片保持现有 Precision Monolith 的黑白灰主色和深蓝辅助色，不使用手写字体，不在人物保护线右侧显示任何内容。

另外两个备选方向未采用：双选对决只适合两个选项，复用范围较窄；结果条形图容易让观众误以为画面展示的是真实投票结果。

## 人物保护线与步骤流程

以 1920×1080 画布的横向 40% 位置作为人物保护线，即 `x = 768`。步骤流程卡仍从 `6.35%`（约 `x = 122`）开始，但宽度由 `52.5%` 缩小到约 `33%`，卡片最右控制在画布 `39.5%` 以内。

React 预览使用百分比边界，Canvas 导出使用对应像素边界。Canvas 卡片最右不超过 `x = 752`，与保护线保留约 16px 缓冲。标题分隔线、步骤分隔线和文字最大宽度一并收窄，不能仅缩放整张卡片或缩小字体。七个步骤继续使用单列纵向时间线，并保留“未来灰、当前深蓝、完成弱蓝”的顺序高亮语义。

## 左侧组件库配色

左侧组件库使用与右侧参数面板一致的三层深灰：

- 标题区使用 `#24282d`。
- 列表区使用 `#1c2024`。
- 底部状态区使用 `#202429`。

组件选中、悬停、边框和深蓝辅助色逻辑保持不变。列表继续隐藏横向与纵向滚动条视觉，但保留滚动能力。

## 投票卡片数据模型

新增动效 ID `audience-poll`，界面名称为“投票卡片”，放在组件库第八位。参数包括：

- `eyebrow`：英文或分类眉题。
- `title`：投票标题。
- `option1` 至 `option4`：四个可编辑投票选项。
- `callToAction`：弹幕或评论引导语。
- `duration`：动画循环时长。

空白选项在预览和导出中自动隐藏，最多显示四项。默认值提供三个选项，正常编辑路径下至少保留两个有内容的选项；历史数据或异常导入不足两项时，渲染器使用两个安全回退选项，避免空卡。

## 投票卡片布局与动画

投票卡与步骤流程卡共用人物保护线约束。卡片从左侧内容区进入，右边缘不超过 39.5%。结构顺序为眉题、标题、选项列表、互动引导语。

动画分为三个阶段：

1. 眉题和标题淡入并轻微上移。
2. 有效选项按编号逐项出现，当前出现项使用深蓝边框和编号强调。
3. 引导语最后出现，并以一次克制的亮度脉冲提醒观众在弹幕或评论区投票。

循环结束时整体淡出。动画不显示虚假的投票比例、票数或结果。

## 预览、导出与持久化

新增 React 组件负责页面预览，独立状态计算器负责确定各阶段透明度和选项状态，Canvas renderer 使用相同阶段语义绘制透明视频帧。`motionRegistry`、Canvas renderer registry、视觉夹具、时间轴和工作区持久化均注册 `audience-poll`。

旧项目中没有该动效或没有投票参数时继续正常加载；新默认值只补充缺失字段，不覆盖用户已有参数。导出区域不包含人物保护线辅助框，保护线只在编辑预览中按现有开关显示。

## 测试与验收

自动化测试覆盖：

- 步骤流程卡 React 与 Canvas 的最右边界均小于人物保护线。
- 左侧组件库三个区域使用确认的深灰色层级，并继续隐藏滚动条视觉。
- 注册表中投票卡片位于第八位，参数控件和默认值完整。
- 投票卡片过滤空白选项、限制最多四项，并在不足两项时安全回退。
- React 预览和 Canvas 导出具有一致的标题、选项和互动引导语。
- Canvas renderer registry 与视觉夹具覆盖全部动效 ID。
- 工作区保存、项目导入和旧项目兼容测试通过。

最终验收运行完整 Vitest、ESLint 和生产构建，并在浏览器中确认步骤流程与投票卡均未越过人物保护线、左侧组件库颜色与右侧参数面板一致、参数编辑可用且控制台无报错。
