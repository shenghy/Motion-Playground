# 七步流程卡片重新设计

## 目标

重新设计卡片 7“步骤流程”，使它在视频左侧稳定容纳最多七个步骤，同时保持右侧完全空白，并避开底部字幕安全区。浏览器预览、透明 MOV 导出和 PNG 序列导出必须保持一致。

## 已确认的视觉方案

采用 B 方案：七步单列时间轴。

- 标题区位于左上方，步骤列表位于标题下方。
- 时间轴固定在视频左侧内容区，右侧不显示任何内容。
- 所有有效步骤始终可见，整体不进入底部字幕安全区。
- 每一步由编号方块、步骤文字和纵向连接线组成。
- 支持 3–7 个有效步骤；空步骤会被过滤，其余步骤自动均匀分布。
- 使用当前项目的银黑视觉语言，并以深蓝色作为辅助色。

## 动画行为

- 焦点从配置的初始步骤开始，依次向下移动并在末尾循环。
- 当前步骤使用深蓝色描边和文字高亮，同时进行轻微放大。
- 已完成步骤保留较弱的蓝色轨迹，帮助观众理解进度。
- 尚未进行的步骤保持灰色，确保层级清楚。
- 七个步骤在动画全过程中均保持可见，不通过隐藏步骤换取空间。
- 系统启用减少动态效果时，停止循环并静态显示配置的初始焦点。

## 参数与数据

- 在 `StepFlowParams` 中新增 `step6` 和 `step7`。
- 组件注册表新增“步骤六”“步骤七”文本控件。
- 初始焦点选项从 1–5 扩展到 1–7。
- 默认内容提供完整七步示例。
- 保留现有分类眉题、流程标题和单步停留时间参数。
- 不提升项目 JSON 版本；旧项目缺少新字段时通过现有默认参数合并机制补齐步骤六和步骤七，保持文件可加载、可编辑和可导出。

## 组件与导出一致性

- React 预览组件从 `step1` 到 `step7` 收集步骤，过滤空值后最多保留七项。
- CSS 使用可变行数的单列网格，在左侧内容区内均匀分配可用高度。
- 纵向路径根据有效步骤数量贯穿首尾节点，不依赖固定五步坐标。
- Canvas 导出渲染器采用相同的步骤收集、位置计算、颜色和焦点规则。
- 导出仍遵守 1920×1080、透明背景和底部字幕安全区约束。

## 兼容性与错误处理

- 有效步骤不足三项时继续使用三步安全回退内容。
- `focusStep` 超出有效步骤数量时沿用现有索引归一化逻辑。
- 文本继续遵守每步最多 12 个字符的限制，超长内容由参数层限制，渲染层保持单行省略保护。
- 旧五步项目加载后会保留原有五步内容，并补入新的默认步骤六和步骤七；用户已有字段不得被覆盖。

## 测试与验收

- 组件测试验证七个步骤全部渲染。
- 验证空步骤过滤后没有视觉空洞，顺序保持正确。
- 验证 1–7 初始焦点与循环顺序。
- 验证减少动态效果下的静态焦点状态。
- 注册表测试验证新增参数、默认值与焦点选项。
- Canvas 渲染测试验证七步输出，并保持预览/导出结构一致。
- 浏览器实测确认右侧为空、七步可读、底部不侵入字幕安全区。
- 最终运行全量测试、Lint 和生产构建。

## 不在本次范围内

- 不增加第八步或动态添加/删除步骤的界面。
- 不修改其他六种卡片。
- 不修改项目 JSON 版本或导出编码格式。
- 不改变右侧参数面板的标签页结构。
