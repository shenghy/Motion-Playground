# Canvas 原始帧透明视频快速导出设计

## 背景与结论

当前透明 MOV 导出会在每一帧把 React 导出舞台交给 `html-to-image`，依次执行 DOM 克隆、计算样式、SVG `foreignObject` 序列化、PNG 压缩，再把 PNG 通过一次独立 HTTP 请求交给 FFmpeg。实测长项目只能达到约 4.4fps，而独立 FFmpeg 编码基准已达到约 48fps，因此当前主要瓶颈是 DOM 转 PNG，不是 ProRes 编码。

本轮采用与 Motion Canvas 相同的核心思路：让导出画面常驻在 Canvas 上。但不引入 Motion Canvas 的场景与生成器体系，也不继续传输 PNG；Overlay Studio 将直接绘制 Canvas，并通过一条持久连接把 RGBA 原始帧顺序送入本地 FFmpeg。

## 目标与验收口径

- 保持输出契约不变：1920×1080、30fps、ProRes 4444、有效 Alpha、无音频、只包含动画卡片。
- 保持第 0 帧时间为 0 秒、总帧数为 `ceil(duration * 30)`，卡片起止边界和层级顺序不变。
- 当前约 6 分 15 秒、11248 帧项目在同一台机器上的完整 MOV 导出总耗时不超过 7 分钟。
- 性能硬门槛为持续不低于 30fps；冲刺目标为不低于 47fps，对应约 4 分钟完成画面生成与编码。
- 3 分钟需要约 63fps，只在真实全链路基准达到该速度时作为额外结果，不通过降低分辨率、帧率、Alpha 或 ProRes 质量换取。
- 编辑器、时间线、参数、项目 JSON、取消导出、保存失败后重试等现有行为保持不变。

完整导出总耗时从创建编码任务开始，到 MOV 成功写入用户选择的文件为止。性能面板继续分别记录绘制、传输与背压等待、FFmpeg 收尾和文件保存时间，避免只报告局部速度。

## 范围

### 本轮包含

- 六种现有动效的 Canvas2D 导出渲染器：核心指标、双栏对比、档案揭示、柱状对比、环形占比、步骤流程。
- 可复用的画布绘制基础设施、字体与纹理资源准备、确定性动画状态计算。
- 基于持久 WebSocket 的 RGBA 原始帧协议，以及 FFmpeg `rawvideo` 输入。
- MOV 与 PNG 序列共用同一套 Canvas 画面生成；MOV 发送 RGBA，PNG 序列在同一 Canvas 上编码 PNG。
- 性能原型门槛、视觉回归、透明通道验证、真实长项目计时。

### 本轮不包含

- 不重写 React 编辑器或正常预览。
- 不引入 Motion Canvas、Remotion、WebGL 或新的时间线模型。
- 不增加新的动效类型、导出格式、分辨率或帧率选项。
- 不并行运行多个 FFmpeg 任务，也不预生成整段视频帧到内存或磁盘。
- 不为了追求 3 分钟目标改变视觉设计或输出质量。

## 架构

### 1. 共享动画状态

每种动效增加一个纯函数状态计算器。输入为参数和卡片局部时间，输出为绘制所需的文本、计数值、进度、透明度、位移、缩放、裁剪比例等语义状态。

React 预览继续使用现有组件与 Motion 动画；确定性导出逻辑和 Canvas 渲染器复用这些纯函数，避免两套实现分别解释延迟、缓动、循环和数字递增。现有 `frameMath` 仍是全局帧时间、卡片活动区间和关键帧插值的唯一来源。

### 2. Canvas 渲染注册表

`MotionDefinition` 增加一个 Canvas 渲染器引用。统一接口接收：

- `CanvasRenderingContext2D`
- 已校验的动效参数
- 卡片局部时间和共享动画状态
- 卡片位置、导出画布尺寸和只读资源集合

渲染器只负责一种动效，不负责遍历时间线、网络传输或编码。公共绘制模块提供网格、铅笔纹理、角标、线段、圆环、文字排版和安全的 `save/restore` 边界，避免六个渲染器重复实现基础效果。

### 3. 常驻导出画布

新的命令式 Canvas 导出舞台只在导出会话开始时创建一张 1920×1080 透明画布并加载字体资源。每帧执行：

1. `clearRect` 清空为全透明。
2. 根据全局帧时间筛选活动卡片，并按 `zIndex` 和稳定次序排列。
3. 计算每张卡片的局部时间与共享动画状态。
4. 使用对应 Canvas 渲染器，在 `save/restore` 隔离中绘制卡片。
5. MOV 路径通过一次 `getImageData` 取得完整 RGBA；PNG 路径从同一 Canvas 生成 Blob。

每帧不触发 React 更新、布局、DOM 克隆、字体 CSS 扫描或 PNG 压缩。字体只在会话开始时等待一次；字体不可用时在创建 FFmpeg 任务前失败，不能悄悄使用不同字体。

### 4. RGBA 持久传输

浏览器创建 MOV 任务后，连接同源本地 WebSocket。每个二进制消息包含 4 字节帧序号和一帧紧密排列的 RGBA 数据：

```text
width       = 1920
height      = 1080
pixelFormat = rgba
bytes/frame = 1920 * 1080 * 4 = 8,294,400
```

同一时刻最多允许一帧等待确认。服务端校验任务、帧序号和精确字节数，将像素写入 FFmpeg `stdin`；只有写入成功并处理完 `drain` 背压后才向浏览器确认该帧。浏览器收到确认后才绘制和发送下一帧，因此内存只保留当前帧与少量传输缓冲，不会累计约 93GB 的整段原始数据。

最后一帧确认后，浏览器发送完成控制消息。服务端关闭 FFmpeg 标准输入，等待编码成功，再沿用现有 HTTP 文件下载与保存重试流程。旧 PNG 帧 HTTP 接口在迁移和回滚期保留，但正式 MOV 路径不再调用它。

### 5. FFmpeg 输入

快速路径使用以下输入语义，输出参数保持现状：

```text
-f rawvideo
-pixel_format rgba
-video_size 1920x1080
-framerate 30
-i pipe:0
-an
-c:v prores_ks
-profile:v 4
-pix_fmt yuva444p10le
-alpha_bits 16
```

Canvas 的透明背景通过 `clearRect` 产生，RGBA 数据直接包含每个像素的 Alpha。FFmpeg 不负责缩放、补帧或合成原视频。

## 分阶段交付与性能闸门

### 阶段一：核心指标原型

先只实现公共 Canvas 舞台、核心指标渲染器、RGBA 协议和 rawvideo FFmpeg 输入，并使用固定 300 帧夹具连续运行三次。基准必须覆盖绘制、`getImageData`、WebSocket 背压和 FFmpeg 写入，而不是只测空 Canvas 或编码器。

- 三次中位数必须达到 30fps。
- 任意一次不得低于 27fps。
- Alpha、分辨率、帧率和 ProRes 4444 验证必须通过。

如果原型未达到门槛，先依据阶段计时定位 Canvas 绘制、像素读取、传输或编码瓶颈。必要时再把绘制迁到 OffscreenCanvas Worker；在达到门槛前不迁移其余五种动效，避免先完成大面积双渲染器重写再发现架构速度不足。

### 阶段二：六种动效迁移

原型过闸后，逐个增加其余五种渲染器和共享绘制原语。每完成一种动效，先通过该动效的状态测试和视觉基线，再接入注册表。任何已知动效缺少 Canvas 渲染器时，导出在任务创建前明确报错，不允许生成缺卡片的成品。

### 阶段三：完整长项目验收

使用包含透明空白、六种动效、卡片重叠和不同位置的混合夹具做三次性能测试，并对用户当前 11248 帧量级项目执行一次完整 MOV 导出。硬验收为总耗时不超过 7 分钟，记录实际平均 fps、各阶段耗时、输出大小和保存耗时；达到 47fps 时同时报告约 4 分钟目标已实现。

## 视觉一致性

React 预览是设计参考，Canvas 成品必须保持：文字内容、字体家族、字号层级、颜色、卡片位置、主要几何结构、动画阶段和透明边缘一致。由于 DOM 与 Canvas 的文字抗锯齿可能产生像素级差异，不要求逐像素完全相等，但不接受肉眼可见的布局漂移。

每种动效固定抽取入场、展开、稳定和循环/收尾至少四个时间点，在透明、黑色和棋盘格背景下并排比较 DOM 参考帧与 Canvas 帧。自动检查包括：

- 画面边界和关键几何位置误差不超过 2px。
- 文字内容和格式化数值完全一致。
- 非透明包围盒与 Alpha 覆盖区域无明显缺失。
- 同一项目、同一帧号重复渲染得到相同像素数据。

视觉基线不通过的动效不能进入完整长项目验收。

## 进度、取消与错误处理

- 进度以服务端已确认写入 FFmpeg 的帧数为准，而不是浏览器刚绘制的帧数。
- ETA 使用确认帧的全链路平均速度计算；FFmpeg 收尾和文件保存继续显示独立阶段。
- 用户取消时立即停止绘制、关闭 WebSocket、终止 FFmpeg，并删除未完成的临时 MOV。
- WebSocket 断开、帧号不连续、帧尺寸错误、消息超限或 FFmpeg 写入失败时，任务失败并清理临时文件。
- 缺少渲染器、字体加载失败或参数无法校验时，在创建编码任务前给出中文错误，避免留下后台任务。
- 最终 MOV 已编码但保存失败时，继续沿用现有重试保存能力，不重新渲染 11248 帧。
- 服务端继续只监听 `127.0.0.1`，校验 WebSocket `Origin`，并保持同一时间只允许一个导出任务。

## 测试策略

### 单元与协议测试

- 六种共享动画状态在关键时间点、循环边界和异常参数下保持确定性。
- 注册表中的每个 `MotionId` 都必须存在 Canvas 渲染器。
- Canvas 舞台只绘制活动卡片，并保持稳定层级、位置和透明清屏。
- WebSocket 拒绝错误任务、乱序帧、重复帧、缺帧和错误字节数。
- 背压确认保证浏览器最多只有一帧在途。
- 取消、断线、FFmpeg 异常和服务关闭都会终止子进程并清理临时目录。
- PNG 序列和 MOV 快速路径在相同帧号使用同一 Canvas 画面。

### 集成与成品验证

- 用真实 FFmpeg 编码 RGBA 测试帧，并使用 `ffprobe` 验证 1920×1080、30fps、ProRes 4444 和 `yuva444p`。
- 抽取首帧、中间帧、末帧，验证透明角落 Alpha 为 0、内容区域存在有效 Alpha。
- 运行现有 Vitest、脚本测试、lint 和生产构建，确保编辑、预览、项目持久化和旧保存流程无回归。
- 运行 300 帧三次性能闸门、混合夹具三次基准和一次 11248 帧量级完整导出。

## 回滚边界

旧 DOM/PNG 捕获链路在本轮迁移期间保留为开发参考和紧急回滚路径，但用户可见的 MOV 导出成功切换后不提供“快/慢模式”开关，也不在快速路径出错时静默降级为几十分钟的旧导出。若阶段一无法达到 30fps，停止扩大迁移范围，保留现有稳定版本并根据计时结果重新评估 Worker 或其他传输方式。
