# Overlay Studio 透明动效导出设计

## 目标

在现有 Overlay Studio 本地网页编辑器中增加两种透明动效导出：

1. 一键导出透明 `MOV / ProRes 4444 / Alpha`，可直接放入剪映专业版、Premiere Pro 或 Final Cut Pro 的上层轨道。
2. 导出透明 PNG 序列，作为无损备用素材或交给其他后期工具重新编码。

导出结果只包含时间轴上的动效卡片。原视频仅用于提供总时长和编辑参照，不参与渲染、编码或文件输出。

## 已确认范围

- 导出完整视频时长，从视频第 0 秒开始。
- 固定输出 1920×1080、30fps。
- 没有卡片的时间段输出完全透明画面。
- 第一帧对应时间 0 秒，导入剪辑软件后放在时间轴 0 秒即可对齐。
- 第一版仅支持最新版 Chrome 或 Edge。
- FFmpeg 随项目依赖准备，不要求用户单独安装或配置环境变量。
- 保留现有视频导入、卡片预览、时间轴、JSON 导入导出、卡片编辑和本地持久化功能。

## 用户界面

右侧参数面板新增“透明动效导出”区域，显示：

- 输出尺寸：1920×1080
- 帧率：30 帧/秒
- 视频时长
- 总帧数：`ceil(videoDuration * 30)`
- MOV 的粗略磁盘占用预估

提供两个独立操作：

- `导出透明 MOV`
- `导出 PNG 序列`

当视频尚未就绪、视频时长无效、时间轴没有卡片或本地编码能力不可用时，按钮禁用并显示中文原因。

导出期间显示格式、当前帧、总帧数、百分比、已用时间和“取消导出”。为保证帧状态一致，导出期间暂时禁止修改卡片、时间轴和参数。预览视频无需参与导出，可以继续保持暂停状态。

MOV 默认文件名为 `Overlay-透明动效-YYYYMMDD-HHmmss.mov`。PNG 序列写入用户选择目录下的时间戳子目录，文件名为 `frame_000001.png`、`frame_000002.png`，依次连续编号。

Chrome 文件系统 API 不向网页暴露绝对保存路径，因此完成状态显示用户选择的文件名或子目录名，不承诺显示完整磁盘路径。

## 确定性透明渲染

新增一个不可见但可截图的导出舞台，尺寸固定为 1920×1080，背景为透明。该舞台不渲染以下内容：

- 原视频或参考人物图片
- 安全区域和字幕区域提示
- 选中边框、拖拽手柄和焦点状态
- 播放控件、时间轴、参数面板和应用外壳

导出时间由帧号计算：

```text
frameTime = frameIndex / 30
cardTime = frameTime - card.start
active = card.start <= frameTime < card.end
```

活动卡片按照 `zIndex`、`position`、`params` 和 `motionId` 渲染。卡片局部时间从自身开始时间归零，循环组件继续按现有循环周期播放，非循环组件在入场完成后保持最终状态，直到卡片结束。

现有组件在正常预览时继续使用 Motion 动画。导出模式通过可选的 `playbackTime` 驱动确定性样式：

- `MotionComponentProps` 增加可选 `playbackTime`。
- 新增纯函数动画时间工具，处理延迟、缓动、关键帧和循环周期。
- 六个动效组件在存在 `playbackTime` 时使用计算后的即时样式，并禁用墙钟驱动的 transition。
- `useCountUp` 在导出模式下直接依据 `playbackTime` 计算数值。

因此同一项目、同一帧号重复导出时得到相同的卡片状态，不依赖电脑速度、浏览器刷新率或截图耗时。

隐藏舞台在开始导出前等待 `document.fonts.ready`。每一帧更新 React 状态后等待布局稳定，再通过 DOM 转图片工具生成带 Alpha 的 PNG Blob。

## PNG 序列管线

PNG 模式使用 `showDirectoryPicker()`：

1. 用户选择目标目录。
2. 创建 `Overlay-PNG-YYYYMMDD-HHmmss` 子目录。
3. 从第 0 帧开始逐帧渲染。
4. 每个 PNG Blob 直接写入对应文件句柄。
5. 写入完成后释放当前 Blob，再处理下一帧，避免把全部序列保存在内存中。

取消或写入失败时停止生成新帧。已经完整写入的 PNG 保留，并显示停止帧号；不会删除或覆盖用户已有文件。

## MOV 编码管线

本地静态服务增加同源导出 API 和独立的导出任务管理器。FFmpeg 使用随项目安装的静态运行文件，不调用系统全局 FFmpeg。

MOV 导出流程：

1. 浏览器通过 `showSaveFilePicker()` 选择 MOV 文件名和位置。
2. 浏览器创建本地编码任务。
3. 浏览器逐帧生成 PNG，并严格按帧号顺序发送到 localhost。
4. Node 将每一帧持续写入 FFmpeg 的 `image2pipe` 标准输入，不在内存中累计全部帧。
5. FFmpeg 将临时输出写为 ProRes 4444 MOV。
6. 编码成功后，浏览器通过流式响应把 MOV 写入用户选定的文件句柄。
7. 文件写入完成后，Node 删除临时 MOV 和任务目录。

核心编码参数：

```text
-f image2pipe
-framerate 30
-vcodec png
-i pipe:0
-an
-c:v prores_ks
-profile:v 4
-pix_fmt yuva444p10le
-alpha_bits 16
```

编码输入中不存在原视频路径或原视频字节，任务接口也不接受视频文件，因此服务端无法把原视频误合成进结果。

## 本地 API 与安全边界

导出 API 仅绑定 `127.0.0.1`，沿用现有本地服务。接口包含：

- 查询编码能力
- 创建随机 ID 的导出任务
- 按连续帧号上传 PNG
- 完成输入并等待编码
- 流式读取成品 MOV
- 取消并清理任务

服务端校验同源请求、任务 ID、帧顺序、PNG MIME、单帧大小、总帧数、分辨率和帧率。每个任务只允许一个活动编码进程。浏览器刷新、连接中断、取消操作或 FFmpeg 异常时终止子进程并删除未完成输出。

同一时刻只允许一个 MOV 导出任务，避免 1080p ProRes 编码争抢大量 CPU、内存和磁盘。

## 错误处理

- 用户取消文件夹或文件选择：返回空闲状态，不创建任务。
- 浏览器不支持文件系统 API：禁用导出并提示使用最新版 Chrome 或 Edge。
- FFmpeg 不可用：PNG 导出仍可使用，MOV 按钮显示本地编码器不可用。
- 帧生成失败：停止任务，显示失败帧号。
- 帧序号中断或重复：服务端拒绝任务并清理。
- FFmpeg 非零退出：显示编码失败摘要，不保留损坏 MOV。
- 用户取消 MOV：关闭上传、终止 FFmpeg、删除临时文件。
- 最终文件写入失败：保留服务器成品至当前任务清理阶段，并提供一次重新保存机会；用户放弃后清理。

## 测试与验收

自动化测试覆盖：

- 帧号到时间的计算和完整视频帧数。
- 卡片开始/结束边界、局部时间、位置和层级。
- 六个组件在指定 `playbackTime` 下输出稳定状态。
- 导出舞台不包含视频、参考图、安全区、选择框和编辑器 UI。
- PNG 连续六位编号和逐帧写入。
- 参数面板的可用、禁用、进度、取消和错误状态。
- API 的能力查询、任务创建、连续帧校验和并发限制。
- FFmpeg 命令包含 ProRes 4444 与 Alpha 参数，且不包含原视频。
- 取消、连接中断、编码失败和完成后的进程及临时文件清理。

人工验收：

1. 导出一段包含透明空白、重叠卡片和多种组件的短项目。
2. 抽查 PNG 四角 Alpha 为 0，卡片区域 Alpha 正常。
3. 使用媒体探测确认 MOV 为 1920×1080、30fps、ProRes 4444，并包含 Alpha。
4. 将 MOV 放入剪映专业版上层轨道，从 0 秒开始，与原视频时间轴对齐。
5. 确认刷新后现有视频、卡片、JSON 和时间轴数据未被导出任务修改。

## 非目标

- 不把动效与原视频合成。
- 不导出 MP4，因为常用 H.264/HEVC MP4 工作流不能稳定保留 Alpha。
- 不增加音频。
- 不增加完整剪辑、转场、字幕烧录或视频导出功能。
- 不支持移动端浏览器、Safari 或 Firefox 的第一版导出。
