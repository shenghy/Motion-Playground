# Overlay Studio 本地网页启动器设计

## 目标

在不重构 React、TypeScript、Vite 项目结构的前提下，为 Overlay Studio 增加稳定的本地网页启动方式。用户双击 Windows 或 macOS 启动脚本后，项目以 `localhost` 网页形式运行，并自动打开默认浏览器。

本阶段只封装启动与本地托管方式，不修改视频导入、卡片预览、时间轴、JSON 导入导出、卡片编辑和现有持久化功能，也不引入 Electron、Tauri 等桌面框架。

当前源码未发现已实现的 SRT 导入入口，只有早期规划文档提到 SRT。本阶段不新增或删除 SRT 功能；如果后续补齐 SRT，它会自然运行在同一本地网页环境中。

## 方案

采用轻量 Node 静态服务器托管 Vite 生产构建目录 `dist`。

启动入口：

- Windows：`启动 Overlay Studio.bat`
- macOS：`启动 Overlay Studio.command`
- 核心逻辑：`scripts/start-overlay-studio.mjs`

启动脚本只负责定位项目目录并调用核心 Node 启动器。核心启动器负责环境检查、依赖准备、生产构建、本地服务、端口选择和浏览器打开。

## 启动流程

1. 以启动脚本所在项目为工作目录，不依赖用户当前终端目录。
2. 检查 `node` 和 `npm` 是否可用；缺失时显示中文错误和安装提示，不继续执行。
3. 如果 `node_modules` 不存在，执行 `npm install`。
4. 执行 `npm run build`，确保本地网页使用当前源代码。
5. 从 `127.0.0.1:4173` 开始寻找可用端口，端口占用时依次尝试后续端口。
6. 使用 Node 内置 HTTP 模块托管 `dist`，不增加运行时服务器依赖。
7. 服务可以访问后自动使用系统默认浏览器打开实际 URL。
8. 启动窗口保持运行并显示访问地址；关闭窗口或按 `Ctrl+C` 后停止本地服务。

浏览器打开方式：

- Windows：系统 `start`
- macOS：系统 `open`
- 其他平台：`xdg-open`

## 本地服务器行为

- 仅监听 `127.0.0.1`，不向局域网暴露。
- 正确返回 HTML、JavaScript、CSS、字体、图片和媒体文件的 MIME 类型。
- 对合法静态资源读取 `dist` 内文件。
- 对前端路由请求回退到 `dist/index.html`。
- 拒绝路径穿越，不允许读取 `dist` 之外的文件。
- 端口搜索范围固定且有限；全部占用时输出中文错误并退出。

## 桌面入口

项目内始终保留两个可复制、可版本控制的启动脚本。

在当前 Windows 机器上额外创建桌面快捷方式，目标指向项目内的 Windows 启动脚本，工作目录指向项目根目录。快捷方式只作为便利入口；即使快捷方式丢失，项目内 `.bat` 仍可直接双击启动。

macOS 的 `.command` 文件写入可执行权限。由于当前执行环境是 Windows，只交付 macOS 启动脚本，不尝试创建远程 Mac 桌面快捷方式。

## 错误处理

- Node/npm 缺失：显示安装 Node.js LTS 的中文提示。
- 依赖安装失败：保留命令输出，暂停窗口供用户查看。
- 构建失败：不启动旧版本服务，显示构建失败。
- 端口全部占用：显示端口范围和处理建议。
- 浏览器打开失败：服务继续运行，并明确打印可手动访问的 URL。
- 静态文件缺失：返回明确的 HTTP 状态码，不泄露本地路径。

Windows 批处理脚本在失败时执行 `pause`，避免双击窗口瞬间关闭。正常启动时窗口保留服务器日志。

## 验证

自动测试覆盖：

- 可用端口选择与端口占用回退。
- 静态文件响应及 MIME 类型。
- SPA 路由回退。
- 路径穿越拒绝。
- 找不到构建产物时返回可理解错误。

机器验证覆盖：

- `npm test -- --run`
- `npm run lint`
- `npm run build`
- 双击等价命令启动服务。
- HTTP 请求验证首页和一个静态资源。
- 浏览器确认 Overlay Studio 可访问。
- Windows 桌面快捷方式存在且目标正确。
- 服务启动后现有编辑器页面和本地持久化入口仍可使用。

## 非目标

- 不打包成安装程序。
- 不引入 Electron、Tauri 或系统托盘。
- 不自动更新应用。
- 不改变 React 页面布局、数据模型和编辑器功能。
- 不在本阶段新增 SRT 导入功能。
